# TV Organizer

כלי לארגון אוטומטי של קובצי סדרות טלוויזיה - זיהוי סדרה/פרק מתוך שם הקובץ, שליפת שם הפרק (אופציונלית) מ-TheTVDB, ומיון הקבצים לתוך ספרייה מסודרת לפי סדרה ועונה.

בפרויקט יש שתי גרסאות עצמאיות, עם אותה לוגיקת ליבה (זיהוי שמות, נרמול תגית פרק, פתרון תיקיית יעד):

| | `tvshows_organizer.py` | `tv_organizer.html` |
|---|---|---|
| איך מריצים | `python tvshows_organizer.py` בטרמינל | פותחים את הקובץ בדפדפן |
| דרישות | Python 3.10+, בלי חבילות חיצוניות | דפדפן מבוסס Chromium (Chrome / Edge) בלבד |
| תיקיות מקור/יעד | קבועות בקוד (`SOURCE_DIR`, `LIBRARY_DIR`) | נבחרות דרך בורר תיקיות, נשמרות בין הרצות |
| תהליך ההעברה | שני שלבים: מיון פנימי בתוך תיקיית המקור, ואז העברה ל-`LIBRARY_DIR` | שלב אחד: ישר ליעד הסופי בספרייה |
| ממשק | טקסט בטרמינל, פס התקדמות ANSI | עמוד HTML עם קוביות סטטיסטיקה, טבלה ולוג חי |
| אישור לפני ביצוע | `Proceed? (Y/N)` בטרמינל | חלון אישור בדפדפן |

## לוגיקה משותפת לשתי הגרסאות

### זיהוי וניקוי שם קובץ

- קובצי וידאו: `.mkv .mp4 .avi .mov .wmv .m4v`, קובצי כתוביות: `.srt`.
- תגית הפרק מזוהה בפורמט `SxxExx` או `NxNN` ומנורמלת תמיד ל-`SxxExx`.
- שם הסדרה מנוקה ומומר ל-`Title.Case` (לשם קובץ) ו-`Title Case` (לשם תיקייה).
- קובצי כתוביות (`.srt`) מקבלים אוטומטית את שם הקובץ של הווידאו התואם, עם סיומת `.he.srt`.

מבנה שם הקובץ הסופי:

```
<Series.Name>.<SxxExx>[.<Episode.Name>][.he].<ext>
```

### שליפת שם פרק מ-TheTVDB (אופציונלי)

שתי הגרסאות משתמשות באותו מפתח API (`TVDB_API_KEY`, מוטמע בקוד) ובאותה לוגיקת חיפוש: ניסיון עם שם הסדרה המלא, ואז וריאציות מקלות (בלי "The/A/An", בלי סיומת מדינה/שנה, שתי מילים ראשונות בלבד). אם הסדרה או שם הפרק בעברית, או שאין התאמה - הקובץ פשוט מאורגן בלי שם פרק, בלי לעצור את התהליך.

### פתרון תיקיית יעד בספרייה

לכל קובץ נקבע יעד לפי המצב של הסדרה בספרייה:

- **סדרה חדשה** - נוצרת לה תיקייה חדשה.
- **תיקיית עונה קיימת** (`Season NN` / `Series NN` / `SNN`) - הקובץ עובר אליה.
- **יש תיקיות משנה אך אין עונה מתאימה** - נוצרת תיקיית `Season NN` חדשה.
- **אין תיקיות משנה כלל** - הקובץ עובר ישירות לתיקיית הסדרה (מבנה "שטוח").

קובץ שכבר קיים ביעד עם אותו שם - תמיד מדולג ולא נכתב מעליו.

### העברת קבצים

שתי הגרסאות מנסות קודם מעבר מיידי (`os.rename` / `FileSystemHandle.move`) שעובד רק כשהמקור והיעד על אותו כונן. אם זה נכשל - מבוצעת העתקה בצ'אנקים עם פס התקדמות חי, ואז מחיקת המקור.

## גרסת CLI - `tvshows_organizer.py`

### דרישות

- Python 3.10+ (נעשה שימוש ב-type hints מסוג `str | None`).
- בלי תלויות חיצוניות - רק מודולים סטנדרטיים.
- מומלץ Windows 10/11 (פס ההתקדמות משתמש בקודי צבע ANSI).

### הגדרת תיקיות

בראש הקובץ:

```python
SOURCE_DIR  = r"C:\Elad\TV"
LIBRARY_DIR = r"H:\TV Shows"
```

לשינוי תיקיות - עורכים ידנית את שני המשתנים.

### הרצה

```
python tvshows_organizer.py
```

### שלבי העבודה

1. **סריקה** - עובר על כל הקבצים ברמה העליונה של `SOURCE_DIR`, מזהה ומנרמל, ושולף שמות פרקים מ-TheTVDB (עם שורת סטטוס מפורטת לכל פרק בטרמינל). קריאות ל-TVDB ממוטמנות לפי (סדרה, פרק) כדי שווידאו וכתובית של אותו פרק לא יכפילו בקשות.
2. **תצוגה מקדימה** - מדפיס את הסדרות שזוהו (קיימות/חדשות בספרייה) וטבלת "לפני → אחרי" לכל קובץ.
3. **אישור** - `Proceed? (Y/N):`. כל תשובה שאינה `Y` מבטלת בלי לגעת בקבצים.
4. **ביצוע בשני שלבים:**
   - **שלב א'** - בתוך `SOURCE_DIR` עצמו: לכל קובץ נוצרת תת-תיקייה בשם הסדרה (סטייג'ינג), והקובץ עובר אליה עם השם החדש. קובץ שכבר במקום/שם הנכונים מדולג (`SKIP - already correct`).
   - **שלב ב'** - כל תיקיית סטייג'ינג עוברת ומתמזגת לתוך `LIBRARY_DIR` לפי לוגיקת פתרון היעד שתוארה למעלה. תיקיית הסטייג'ינג הזמנית נמחקת אם התרוקנה. אם `LIBRARY_DIR` לא נמצא - הקבצים נשארים ממוינים בתוך `SOURCE_DIR` עם אזהרה.

### פלט לדוגמה

```
=================================================================
  TV File Organizer
  Source  : C:\Elad\TV
  Library : H:\TV Shows
=================================================================

Detected series (1):
  - Breaking Bad  (2 file(s))  [exists in library]

Planned renames (2 file(s)):
  Breaking.Bad.S01E01.720p.mkv  -->  Breaking.Bad.S01E01.Pilot.mkv
  Breaking.Bad.S01E01.srt       -->  Breaking.Bad.S01E01.Pilot.he.srt

Will perform:
  - Rename files
  - Move video and SRT files (originals removed)
  - Move new series folders to library, or merge into existing ones
Proceed? (Y/N):
```

בסיום מודפסת שורת סיכום (`Done: X file(s) processed successfully, Y error(s).`), ואם היו שגיאות - רשימת הקבצים שלא טופלו.

## גרסת דפדפן - `tv_organizer.html`

### דרישות

- דפדפן מבוסס Chromium (Chrome / Edge) - משתמש ב-File System Access API, שלא נתמך ב-Firefox/Safari.
- אין צורך בהתקנה, שרת, או חיבור לאינטרנט (מלבד שליפת שמות פרקים מ-TheTVDB, שהיא אופציונלית).
- פשוט פותחים את `tv_organizer.html` בדפדפן.

### שלבי העבודה

1. **תיקיות** - בוחרים דרך בורר תיקיות של הדפדפן תיקיית **SRC** (מקור) ותיקיית **LIB** (ספרייה, למשל `H:\TV Shows`). ההרשאות והמזהים נשמרים ב-IndexedDB בין פתיחות, כך שאין צורך לבחור מחדש בכל פעם. כפתור **"שכח תיקיות שמורות"** מנקה את השמירה.
2. **סריקה** - לחיצה על "סרוק תיקיית מקור" עוברת על הקבצים, מזהה ומנרמלת אותם, ואם הצ'קבוקס "חפש שמות פרקים ב-TheTVDB" מסומן - שולפת שמות פרקים ופוסטר לסדרה. בסיום מוצגות רשימת הסדרות שזוהו, טבלת "לפני → אחרי", ושלוש קוביות סטטיסטיקה (סדרות שזוהו / סה"כ קבצים / זמן סריקה).
3. **ביצוע** - לחיצה על "בצע שינוי שם והעברה" (אחרי אישור בחלון קופץ) מעבירה כל קובץ ישירות ליעד הסופי בספרייה. שלוש קוביות סטטיסטיקה מתעדכנות בזמן אמת:
   - **ממתינים** - כמה קבצים נותרו לטיפול (יורד עם כל קובץ שמטופל).
   - **עובדו** - כמה קבצים הועברו בהצלחה עד כה.
   - **זמן ביצוע** - מוצג רק בסיום, הזמן הכולל שלקח הביצוע.

   יומן פעולות מציג שורה לכל קובץ (אייקון וידאו/כתובית, יעד, פס התקדמות), ובסיום שורת סיכום באנגלית (`Done: X files processed successfully, Y errors/skipped.`).

### הערות טכניות

- אין רכיב שרת - כל הפעולות קורות ישירות מול מערכת הקבצים המקומית דרך הדפדפן.
- אם אין גישה ל-TheTVDB (למשל חסימת CORS) - מוצגת התראה בראש הדף והתהליך ממשיך בלי שמות פרקים.

### טאב Auto Sync - סנכרון תרגומים אוטומטי

מסנכרן את כל קובצי ה-SRT בתיקייה לפסקול של הפרקים, בעזרת [ffsubsync](https://github.com/smacke/ffsubsync). הכלי מזהה את ההזזה בנפרד לכל פרק, וגם מתקן הפרשי framerate. בתוך פרק ההזזה יכולה להשתנות, למשל בכל הפסקת פרסומות, כשהתרגום נעשה לגרסה עם חיתוכים שונים. הכלי מחלק את הפרק לקטעים ומסנכרן כל קטע בנפרד. בגבול בין קטעים, שורות יכולות להתחלף בסדר או לחפוף זו לזו. לכן אחרי הסנכרון השורות מוחזרות לסדר המקורי שלהן, וכל חפיפה מתוקנת: השורה המאוחרת זזה לזמן הפנוי שאחריה. אם אין מספיק זמן פנוי, השורה הקודמת מתקצרת, אבל לא לפחות מ-0.8 שניות. לפעמים הכלי מזהה בטעות "אי": קטע קצר שההזזה שלו רחוקה מאוד (יותר מ-5 שניות) גם מהקטע שלפניו וגם מהקטע שאחריו, בזמן ששני השכנים קרובים זה לזה. זה לא חיתוך אמיתי, ולכן הקטע מקבל את ההזזה של השורות שלפניו. בנוסף, הכלי מזהה נכון שההזזה משתנה, אבל לפעמים ממקם את הגבול בין הקטעים כמה שורות (ואפילו כמה דקות) רחוק מדי. לכן כל גבול מוזז לרווח בין שורות שארוך מספיק כדי להכיל את הזמן שנחתך. רווח שיש בו שורת "+" מקבל עדיפות, כי מתרגמים משאירים שורה כזו בכל הפסקת פרסומות. אם אין רווח כזה, הגבול עובר לרווח המתאים הקרוב ביותר.

**מול מה מסנכרנים:** אם יש בקובץ הווידאו רצועת תרגום אנגלית בפורמט טקסט, הסנכרון נעשה מולה, וזה הכי מדויק. אחרת, מול רצועת שמע אנגלית. רק אם אין אף אחת מהן, הסנכרון נעשה מול רצועת השמע הראשית. ההעדפה הזו חשובה בגרסאות זרות, שבהן רצועת השמע הראשית היא לרוב דיבוב, והדיבוב מבלבל את הסנכרון.

**דרישות (חד-פעמי):** `pip install ffsubsync`, ‏`winget install Gyan.FFmpeg`, ו-`start_helper.bat` שרץ ברקע. הדפדפן לא יכול להריץ תוכנות, ולכן העבודה עצמה נעשית ב-`helper.py`.

**איך זה עובד:**
- מכניסים נתיב תיקייה ולוחצים **Run sync**. נסרקת רק הרמה העליונה של התיקייה, בלי תתי-תיקיות.
- לכל קובץ וידאו מותאם SRT באותו שם (`X.srt` או `X.he.srt`). אם אין כזה, מותאם SRT יחיד עם אותה תגית `SxxExx`. פרק בלי התאמה, או עם יותר מהתאמה אחת, מדולג ומופיע בלוג.
- ה-SRT המסונכרן מחליף את המקורי באותו שם, בקידוד UTF-8 עם BOM. המקורי נשמר קודם בתת-תיקייה `_original_subs`. בהרצה חוזרת הסנכרון מתחיל שוב מהמקור השמור, ולא מהתוצאה הקודמת. אם בינתיים הורד קובץ תרגום חדש, הוא הופך למקור החדש.
- הלוג מציג לכל פרק מול מה הוא סונכרן, שעה, הזזה, framerate, מספר הקטעים וזמן ריצה. בסוף מסומנים לבדיקה ידנית פרקים עם framerate שונה מ-1.000, או עם הזזה רחוקה ביותר מ-10 שניות מהחציון של שאר הפרקים.
- **Stop** עוצר מיד. הפרק שבעבודה נשאר ללא שינוי.

בדיקות ללוגיקת ההתאמה: `python -m unittest discover -s tests`

## הערה משותפת

מפתח ה-API של TheTVDB מוטמע בקוד בשתי הגרסאות (`TVDB_API_KEY`). ניתן להחליף אותו במפתח אישי דרך [thetvdb.com/dashboard/account/apikey](https://thetvdb.com/dashboard/account/apikey). כשל בתקשורת מול TheTVDB לא עוצר את התהליך באף אחת מהגרסאות - הקובץ פשוט מאורגן בלי שם פרק.
